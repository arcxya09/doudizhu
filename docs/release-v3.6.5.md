# 闲来斗地主 v3.6.5

选分、发牌节奏与电脑牌力修复版，versionCode 24，可直接覆盖安装并保留牌局、战绩、设置与本地音乐。

## 1. 叫分

此前人类玩家只能"叫地主"（即 3 分）或"不叫"，**没有办法叫 1 分或 2 分**；而三台电脑早就会按牌力叫 1/2/3 分。规则层 `Game.bid` 一直支持 1..3，语音素材 `bid_1/2/3` 也一直在包里，只有 UI 被写死成 3 分。

- 叫分阶段改为 **不叫 / ∞ / 1分 / 2分 / 3分**，分数不高于当前最高叫分时按钮变灰（复用"无可出"那套禁用逻辑），3 分保持橙色主按钮。
- 人类叫分改播对应语音：叫 1 分播 `bid_1`，2 分播 `bid_2`，3 分播 `bid_3`（此前无论叫几分都播 `bid.wav`）。`AudioCues.forLandlordCall` 随之删除。
- 操作栏由屏宽 50% 放宽到 62% 以容纳五个控件；按钮本来就居中，出牌阶段的观感不变。

## 2. 发牌节奏

原来每张牌间隔 50 ms 单独发出，一轮三张只要 150 ms，17 轮 2.55 秒就发完了，而 `deal.wav` 是 3.94 秒——**动画比音效快约 40%**，所以听起来和看起来各走各的。

把音频包络拆开后可以看到它其实有 **17 次清晰的拍击声**，间隔约 234 ms，正好就是 17 轮 × 3 家 = 51 张：

```
0.10  0.31  0.53  0.77  1.00  1.23  1.46  1.68  1.92
2.16  2.41  2.67  2.92  3.16  3.40  3.62  3.85   (秒)
```

- 改为**一轮一拍、三张牌相差 20 ms 依次飞出**，17 拍严格贴住上面这 17 个实测拍点。
- 单张飞行时长 260 ms，比拍间隔略长，每张都在下一拍响起前落定。
- 三张底牌在最后一拍之后补发。
- 首次启动时局是新的但音频焦点要等 `onResume` 才拿到，原来动画会先跑、声音后响；现在把时间线推迟到 `onResume` 之后启动，两者共用同一个起点。

## 3. 电脑牌力与农民协作

三处具体缺陷：

- **评估函数不是"还要出几手"。** 原来按点数组加权给顺子一点奖励，分不清"34567 是一手牌"和"五张散牌是五手牌"，于是会拆顺子、留散牌。现在用 `handsLeft()`：按顺子/连对/飞机/炸弹逐一抽取后统计剩余手数，三带一自动抵消一张单牌，并取几种抽取顺序里最省的一种。
- **队友快走完时不喂牌，方向还是反的。** 队友只剩 1–2 张且紧接着自己出牌时，本该领一张**小单**让他直接走掉，原来的 `+m.key*.2` 却**偏好大牌**。现在改成领最小的单张。
- **对手剩 1 张时领牌不看能不能被压。** 原来对所有单张一律 `+8`，等于没有区分。现在对非单张按张数加权（宁可一手多出几张），对单张则偏好点数大的——手里有大王就该出大王，而不是领张小 3 送人头。

自对弈实测（同一批 300 个种子，座位 0 固定当地主）：

| | 改前 | 改后 |
| --- | --- | --- |
| 困难地主 vs 简单农民 | 61% | **80%** |
| 简单地主 vs 困难农民 | 4% | 3% |

阈值已按 80% 收紧到 `>70%`，锁住这次的提升而不是只验证"能赢随机"。

## 测试

单元测试 22 → 27 项：

- `handsLeft` 计数正确性：顺子/连对/飞机/炸弹/王炸各算一手，五张散牌算五手，三带一算一手。
- **发牌拍点回归**：直接从 `deal.wav` 重新解析包络取出拍击位置，逐一核对动画节拍表（±40 ms）。以后谁换了音频素材，这个测试会立刻失败。
- 农民喂牌：队友剩 1 张且紧接着自己出牌时，领出最小单张。
- 对手剩 1 张时领导：偏好对手单张压不过的对子，而不是小单张。

设备测试补充：叫分前 1/2/3 分全部可点，当前最高叫分为 2 时 1 分与 2 分变灰、3 分仍可点；点 3 分后地主上牌 20 张、播报为 `bid_3`、底分记为 3。

本机验收：单元测试 28 项通过，`:app:lintDebug` 无错误，1280×720、1920×1080、1.3 倍字体、1280×588 宽屏四种配置各 3 项设备测试全部通过。

## 发布校验脚本同步

`scripts/check-release-upgrade.sh` 用按钮文案判断"应用是否恢复到了人类回合"，此前只认 `叫地主` 和 `提示`。本次把叫分按钮改成 1/2/3 分后，该探针再也匹配不到人类回合，**v3.6.5 的首次 CI 在真机升级校验这一步超时失败**（签名 APK 已构建完成，但发布步骤被跳过，所以没有发出坏版本）。

- 探针文案扩充为 `叫地主 / 不叫 / 1分 / 2分 / 3分 / 不出 / 提示`：既认旧版本的 `叫地主`，也认新版本的三档叫分。
- 新增 `ReleaseProcessTest`，从 `render()` 的动作区里提取按钮文案，逐一核对发布脚本是否认识；改动按钮文案而忘了同步脚本会立刻测试失败（已通过故意改名验证会触发）。
- 把该脚本声明为测试输入，编辑脚本会强制重跑单元测试——否则 Gradle 认为测试是最新的，本地根本不会发现。
