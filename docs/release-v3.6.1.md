# 闲来斗地主 v3.6.1

存档与牌桌修复版，versionCode 20。

## 重要：本版更换了签名证书

原私人签名备份不可用，本版使用新生成的永久证书（指纹 `22764e23…a31a`，旧指纹 `59ed2222…d86a3` 作废）。

**已安装 v3.6.0 的手机无法覆盖升级**，必须先卸载再装本版；卸载会清除牌局、战绩、设置和导入的本地音乐。此后同一新证书继续沿用，v3.6.1 之后的正式版可以正常覆盖安装并保留数据。新私人备份必须妥善保存，丢失后无法再更新。

## 修复

- **地主角标指向真正的三张底牌。** 此前角标画在手牌最右一张（点数最小）上，与底牌无关；叠牌只露出左侧一条，右上角标会被后一张牌盖住。现在三张底牌各自在露出条内画金色标记，开局看底牌后能直接在手里找到它们。
- **普通、困难电脑不再每一步都一样。** 同一手牌此前永远走同一条线，容易被摸透。现在在评分相差不到 0.25 的等价出法中随机选择，只影响可互换的同类选择，不会退化成炸弹或高牌。

## 加固

- **存档结构不再因为加字段而失效。** `Game`、`Move`、`SavedTable` 固定了 Java 序列化 UID（取声明前的实际值）。此前任何字段增删都会改变 UID，`restore()` 的兜底 catch 会连带清空玩家存档与战绩。
- **战绩与牌局分开保存。** 战绩写入独立的 `record` 存储，牌局写入带格式号的 `native-table-v3`。牌局记录损坏时只重开本局，战绩、设置与本地音乐不受影响，并会提示"存档无法读取"。
- **旧存档保持可读且不再被改写。** `native-table-v2` 只读不写，v3.6.0 的存档继续能恢复；发布流程要求该文件在覆盖安装后逐字节不变。
- **恢复前校验牌局。** 恢复时会检查难度、座位、阶段、手牌与底牌是否自洽，不合格的记录按损坏处理，不再让残缺存档在 `render()` 里崩溃。
- **返回键迁移到 `OnBackInvokedDispatcher`。** Android 13 及以上走新的返回回调，旧版本保留 `onBackPressed` 兜底，两者共用同一段保存并退出的逻辑。

## 测试

单元测试由 10 项增加到 22 项：

- 新增 `SaveFormatTest`：直接读取从 v3.6.0 安装中取出的真实存档文件，验证仍可反序列化、且重新序列化后逐字节一致；覆盖快照往返、校验拒绝与 UID 固定。
- 修正出牌穷举对照的取样偏差：此前固定取排序后的前 11 张，永远不含 2 和王；现在随机取子集，并断言样本确实覆盖 2 与王。
- 补充 `beats()` 压制矩阵、计分矩阵（地主 0/1/2、农民视角）、炸弹与王炸翻倍、重新发牌与非法出牌拒绝、牌型边界（三组与四组飞机、飞机带单/带对、四带二带两单、双王不可作翅膀、顺子连对飞机主体不含 2 和王）。
- 新增 AI 随机性测试：同一手牌会出现不同出法，且每个选择都在合法出法集合内。

本机验收：`:app:testDebugUnitTest` 22 项通过，`:app:lintDebug` 无错误，模拟器 1280×720 原生界面与音频两项设备测试通过，并实际执行了一次覆盖安装：安装前后与恢复后 `native-table-v2` 哈希均为 `36e02f35…baa7`，牌局成功恢复，`native-table-v3` 与 `record.xml` 正常建立。发布验收脚本改为按基线实际写入的存档文件计算哈希，换格式的版本同样受检。
