# 全软件审查与改进 · 2026-10-09

基线为 v3.6.5。审查覆盖规则与状态机、电脑策略、原生 View/Canvas、触控和无障碍、生命周期、存档与战绩、声音和本地音乐、Manifest 与构建发布流程。本次改动用于 v3.7.0，下文记录发布前的审查和本地验收。

## 已修复问题

| 严重度 | 问题与实际影响 | 修复 |
| --- | --- | --- |
| P1 | `onResume()` 在发牌期间仍安排电脑回合，电脑可在牌未发完时叫分甚至领走底牌，重绘会打断飞牌。 | 调度入口和执行入口均检查发牌状态；发牌完成后再安排下一回合，重开前解除旧动画监听。 |
| P1 | 目标牌存在但出牌座位为 -1 的存档通过校验，启动时下标越界；跨座位重复牌、伪造牌型和错误结算也可能恢复。 | 验证完整阶段、座位、牌张、上手牌型、轮转、底牌归属及结算关系，拒绝反序列化注入的空字段。 |
| P1 | 独立战绩先于牌局写入；牌局写失败时，已计分结果可能对应旧牌局，恢复后重复计分。 | 快照一起保存牌局和战绩，成功后才更新独立镜像；启动时用快照修复过时镜像。 |
| P2 | 仅有 AtomicFile 备份时被判定无存档；当前档损坏时可能复活很久以前的 v2 牌局。 | 读取 `.bak`；只有完全没有当前存档时才迁移旧牌局，损坏时保留独立战绩并重新发牌。 |
| P2 | 点击已抬起牌的顶部会误选后方相邻牌；滑选被系统取消或第二根手指打断后仍遗留错误选择。 | 使用真实绘制牌面做命中测试；取消时回滚到手势开始前的选择，多指手势锁定到松手。 |
| P2 | 回合提示几乎一直不可见，底栏空白；帮助按钮实际打开设置。 | 顶部独立显示当前回合，下方给出操作说明；帮助打开完整玩法与操作说明。 |
| P2 | 已保存但无法解码的本地音乐每次启动反复尝试；异常旧音量可能超出范围。 | 回退默认音乐时清理失效选择，异步清理不能覆盖新导入；音量限制在 0–100。 |

## UI / UX

保留横屏原生牌桌、现有背景与扑克牌素材。选中手牌增加淡金底色和描边，当前座位更醒目，记牌器数字提高对比度。禁用操作保留清晰文字，灰色牌面区分不可用状态；手牌、公共牌、地主底牌分别提供正确无障碍语义。切换托管时清除旧选牌，底栏展示接管说明。超过两行的公共牌条使用实际行数分配高度。

## 电脑策略

- 按点数枚举飞机和四带翅膀，消除仅花色不同的重复搜索。
- 以缓存搜索计算最少合法出手数，包括三带二、飞机翅膀、四带及重叠顺子；同一次决策复用所有候选的拆手缓存。
- 困难农民会阻拦紧接着行动、只剩单张或对子的地主；若队友这手不可能被超越，继续让牌。
- 王炸后能一手走完时先保住出牌权；面对王炸直接不出。
- 对拆手数相同的候选，考虑小散单负担与高对子、三张的控牌能力；对手剩单张时避免领出容易被压过的小单，紧接着的农民队友也剩单张时优先喂牌。
- 电脑仍只使用自己的手牌、公开目标牌、身份和余牌数。最少出手数是自身手牌的精确拆解，不代表对整局胜率的精确求解。

## 验证与兼容

保留 `Game`、`Move`、`SavedTable`、`TableSnapshot` 的序列化 UID。新增可空战绩字段，旧 v3 存档缺字段时读取为 null；真实旧 v2 记录仍逐字节重序列化一致。兼容测试包含由修改前编译类生成的旧 v3 二进制样本。

测试覆盖独立子集穷举与合法组合对照、完整对局、残局战术、每一步牌局状态校验，以及真实设备触控、发牌、托管、声音解码、损坏音乐回退、存档备份、战绩镜像和写失败恢复。设备脚本同时验证 JUnit 成功摘要与 instrumentation 正常结束，测试数量增加不再误判失败。

### 电脑对照与性能

最终代码完成 3,000 局对照。每局固定座位 0 当地主、叫 3 分，两位农民使用同一版本的策略；表中均为地主获胜局数，基线是本轮修改前的困难策略。完整输出见 [种子 1–300](benchmarks/ai-final-1-300.txt) 和 [种子 401–700](benchmarks/ai-final-401-300.txt)，其中记录了基线提交与算法文件 SHA256。

| 样本种子 | 新困难地主 / 旧困难农民 | 旧困难地主 / 旧困难农民 | 旧困难地主 / 新困难农民 |
| --- | --- | --- | --- |
| 1–300 | 138 / 300 | 143 / 300 | 129 / 300 |
| 401–700（未参与调权） | 140 / 300 | 132 / 300 | 125 / 300 |

这些样本支持本次农民配合的改进，地主结果存在波动，不能据此宣称所有局面或真人对战的胜率必然提高。困难对简单的固定 1–300 样本中，困难地主赢 250 局，简单地主对困难农民赢 6 局；该对照只是难度回归，不代表新旧策略的直接提升幅度。

最终代码在运行对局后的桌面 JVM 中，对种子 1–300 的 300 手随机地主牌及 3 类构造复杂 20 张手牌采样，平均决策 1.95 ms、P95 4.77 ms、最大 24.76 ms。这不是冷启动或实体手机耗时保证。运行方法与原始结果位置见 [AI 基准说明](AI-REVIEW.md)。
