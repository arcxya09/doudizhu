# 发牌动画设计（v3.6.2）

## 背景

`fresh()` 目前只调用 `audio.requestDeal()` 播放 3944 ms 的 `deal.wav`，`render()` 立即把手牌全部画出来，没有任何过渡。玩家听得到发牌声，却看不到发牌过程。

## 约束

- 对手的手牌本来就不画牌面，只显示余牌数字徽章；座位上的 `CardStrip` 是出牌区，不是手牌。
- `HandLayout` 与 `CardStrip` 默认 `clipChildren=true`，牌飞出自身边界会被裁剪。
- 项目要在五种显示配置下验收：1280×720、1920×1080、1.3 倍字体、1280×588 宽屏、模拟挖孔屏。
- 玩家不限时，发牌不应变成强制等待。
- 恢复存档不得重放发牌（`requestDeal()` 本来就只在 `fresh()` 调用）。
- CI 的 `disable-animations: true` 会把动画缩放设为 0，`ValueAnimator` 会立刻结束，因此测试只能断言结束态。

## 机制选型

选定 **真牌 view 原地飞入**：手牌区的 17 张 `CardFace` 先按最终位置排好，每张以 `translation` 移到牌堆、`alpha=0`、略微缩小，再按次序飞回原位。

- 落点就是牌的真实排布位置，不存在与"落地牌"对齐偏差，也不需要把 `CardFace.onDraw` 抽成公共绘制函数。
- 否决"独立覆盖层重画牌面"：需要抽出公共绘制、还要保证落点像素对齐，易出现 1 帧跳变。
- 否决"逐张 addView"：手牌居中排布，每加一张全体左移，观感是"挤"而不是"发"。

对手两张没有牌面 view，用一个全区域 fx 层 `DealLayer` 承载它们的牌背飞行。

## 时序

对齐 `deal.wav` 的 3944 ms：

| 项 | 值 |
| --- | --- |
| 起始延迟 | 300 ms（等洗牌声起） |
| 主牌序 | 51 张按 `我 → 小林 → 老周` 轮转 |
| 发牌间隔 | 55 ms |
| 单张飞行 | 340 ms |
| 底牌 | 最后 3 张，背面朝上（`card=54` 已是"未公开底牌"） |
| 总时长 | 约 3200 ms，留余量给音效收尾 |

同一时刻约 6 张在空中，形成连续牌流。

## 坐标

- 牌堆：桌面中心偏上 `(0.5, 0.30)`，换算到各容器自身坐标系。
- 手牌：`HandLayout` 内第 i 张的静止位是它的 layout 位置，故 `translation = (牌堆 − layout 位置) × (1 − p)`。
- 底牌：同样在 `CardStrip` 内原地飞入。
- 对手：`DealLayer` 子 view 统一 layout 在 `(0,0)`，用 `x`/`y` 绝对定位，目标为左右余牌徽章附近。
- 飞行带轻微抛物弧线，`scale` 由 0.82 升到 1.0，前 40% 淡入。

## 状态机

新增 `dealing` 标志：

- `fresh()`：建局 → `persist()` → `dealing=true` → `render()`（不构建操作栏）→ `requestDeal()` → 启动时间线。
- 发牌期间不调用 `render()`，避免 `removeAllViews()` 打断动画；对手余牌数字由时间线直接更新 `0 → 17`。
- 结束：取消动画、`dealing=false`、`render()`、`schedule()`。
- 跳过：发牌期间 `DealLayer` 可点击，点任意位置立即结束；结束后置为不可点击，不再拦截触摸。
- `onPause`：立即收尾并持久化。
- `redeal`（无人叫分）：重新走一次完整发牌。
- 恢复存档：`dealing=false`，直接正常渲染。

## 测试

- 新增 `testDeal()` 测试钩子触发一次发牌，设备测试断言结束后 17 张手牌齐全、操作栏出现、无崩溃。因为断言的是结束态，动画缩放为 0 时同样成立。
- 现有 `testStart()` 不经过 `fresh()`，不受影响。
- 单元测试不涉及视图，无需改动。
